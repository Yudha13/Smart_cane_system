# Contributing

The project is in Phase 0 engineering validation. Requirements, architecture, and test-strategy contributions are welcome. Production firmware, hardware build files, and deployment configurations are not yet authorized.

## Workflow
1. Read `AGENTS.md` and relevant documents under `docs/`.
2. Document the proposed change and rationale.
3. Keep changes focused and preserve existing decisions.
4. Include tests or explain why testing is not applicable.
5. Update documentation and `CHANGELOG.md` for meaningful changes.
6. Never include secrets, private keys, personal data, or production configuration.

A hardware claim must identify the exact model, setup, procedure, measured result, and date. A software test report must include the command and observed outcome. Planned, mocked, or simulated tests are not field validation.

Pull requests must describe scope, risks, affected subsystems, validation, and rollback considerations. Architecture changes require explicit owner approval.
